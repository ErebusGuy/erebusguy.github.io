Naming conventions

public class Forklift
{
    private int _speed;
    private static int s_forkliftCount;

    public int Speed { get; set; }

    public void StartMotor() { }
}
Style Usually used for Example
PascalCase Classes, methods, properties ForkliftController, StartMotor()
camelCase Local variables, parameters currentSpeed, operatorName
_camelCase Private instance fields _motorTemperature
s_camelCase Private static fields s_totalForklifts

Access modifiers

Think: who is allowed to access this?

public
Accessible from outside the class.
private
Only accessible inside the same class.
protected
Accessible in the class and derived classes.
internal
Accessible inside the same assembly.
protected internal
Same assembly OR a derived class elsewhere.
private protected
Same assembly AND the same/derived class.
For now, the big two are: public = outside code can use it and private = only this class can use it.

Fields vs properties vs methods

Field

Stores data.

private int _speed;

Property

Controls access to data.

public int Speed { get; set; }

Method

Performs an action.

public void Start()
{
    Console.WriteLine("Machine started");
}
Automation analogy:
field = internal machine state
property = exposed value/tag
method = command/function

Properties

Read + write

public int Speed { get; set; }

Outside code can both read and change the value.

Public read, private write

public int Speed { get; private set; }

Outside code can read it, but only the class itself can change it.

Read-only property

public string SerialNumber { get; }

public Forklift(string serialNumber)
{
    SerialNumber = serialNumber;
}

Full property with validation

private int _speed;

public int Speed
{
    get => _speed;

    set
    {
        if (value < 0 || value > 20)
        {
            throw new ArgumentOutOfRangeException(nameof(value));
        }

        _speed = value;
    }
}

value is the new value someone is trying to assign.

Think of validation as an interlock. Outside code asks for a value; the class decides whether that value is allowed.

Constructors

A constructor runs when you create an object with new.

public class Forklift
{
    public string SerialNumber { get; }

    public Forklift(string serialNumber)
    {
        SerialNumber = serialNumber;
    }
}

Forklift truck = new Forklift("FL-001");
Constructor rules: same name as the class, no return type, runs during object creation.

=> expression-bodied syntax

This:

public int GetSpeed() => _speed;

is a shorter version of:

public int GetSpeed()
{
    return _speed;
}

Likewise:

public Forklift(string name) => Name = name;
For now, think of => as: “do or return this one simple thing.”

Instance vs static

Instance member

private int _speed;

Each object gets its own copy.

Static member

private static int s_forkliftCount;

Shared by the class rather than belonging to one object.

instance = this machine
static = the class / all machines

this

this means the current object.

private string _name;

public Forklift(string name)
{
    this._name = name;
}

Often the same code is simply written as:

_name = name;

Common exceptions

Exception Use / meaning
ArgumentException The argument is invalid in a general sense.
ArgumentNullException An argument that should contain an object is null.
ArgumentOutOfRangeException The value exists but is outside the allowed range.
InvalidOperationException The action is normally valid, but not in the object's current state.
NullReferenceException Your code tried to use an object reference that is null.
IndexOutOfRangeException Your code tried to access an array index that does not exist.
DivideByZeroException Integer code attempted to divide by zero.

Examples

if (name == null)
{
    throw new ArgumentNullException(nameof(name));
}

if (speed < 0 || speed > 20)
{
    throw new ArgumentOutOfRangeException(nameof(speed));
}

if (!_engineRunning)
{
    throw new InvalidOperationException(
        "Cannot drive while engine is stopped."
    );
}
Quick guide:
bad argument → ArgumentException
null argument → ArgumentNullException
outside limits → ArgumentOutOfRangeException
wrong machine/object state → InvalidOperationException

nameof

Prefer this:

throw new ArgumentNullException(nameof(name));

over manually typing the variable name as a string:

throw new ArgumentNullException("name");

If the variable gets renamed later, nameof stays safer and clearer.

Methods, parameters, and arguments

Method with no return value

public void StartMotor()
{
    Console.WriteLine("Starting motor");
}

void means the method returns no value.

Method that returns a value

public int GetSpeed()
{
    return _speed;
}

Parameter vs argument

public void SetSpeed(int speed)
{
    _speed = speed;
}

machine.SetSpeed(10);

parameter = speed in the method definition
argument = 10 passed into the method

Classes and objects

Class

public class Forklift
{
}

Think: blueprint / design.

Object

Forklift truck = new Forklift();

Think: actual machine built from the blueprint.

Main mental model

FIELDS

What information does this object store?

PROPERTIES

What information can outside code see or change?

METHODS

What actions can this object perform?

PUBLIC

What am I exposing to the outside world?

PRIVATE

What am I keeping inside the control cabinet?

STATIC

Does this belong to one object, or the class as a whole?

EXCEPTIONS

What situations should this code refuse to allow?

Automation shorthand

public property ≈ HMI-visible/tag-accessible value
private field ≈ internal machine state
method ≈ command/function
private setter ≈ observable externally, changed internally
validation ≈ limits/interlocks
exception ≈ “this operation is not permitted”
